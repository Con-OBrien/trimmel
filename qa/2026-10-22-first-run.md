# QA report: PC Optimizer v0.1.0 (first run, 2026-10-22)

Scope: code read of the whole repo plus `go test ./...` (cleanup, mover and oldver pass). The app was not run, so every item is a code-level risk that needs a real-machine check.
Packages with no tests: auth, drivers, startup, procs, overview, elevation.

Status key: OPEN, FIXED (see the fix commit), WONTFIX.

## High

| ID | Status | Summary |
| --- | --- | --- |
| H1 | FIXED (uncommitted) | Standard-user PCs: the app runs as the admin account entered at the UAC prompt, so cleanup, startup and sign-in act on the wrong profile. |
| H2 | FIXED (uncommitted) | Starting offline deletes the stored sign-in token, then blocks the app behind a login that needs the network. |
| H3 | FIXED (uncommitted) | Published build has no Google client ID compiled in (no `.env.local`, 0 matches in the shipped exe), so sign-in is silently absent. |
| H4 | FIXED (uncommitted) | Move apps copies with `/COPY:DAT`, dropping ACLs and ownership. Files in `Program Files` can become writable by ordinary users. |
| H5 | FIXED (uncommitted) | A moved program breaks if the destination drive is removable or gone, with no warning and no indication in the list. |

### H1. Wrong account on standard-user PCs
`requireAdministrator` plus a standard user means UAC asks for admin credentials and the app runs as that admin. Per-user targets then resolve to the admin profile: `%TEMP%`, browser caches, `CrashDumps`, HKCU startup items, the Recycle Bin and the Credential Manager token. The user's own junk is untouched and the app shows the admin's data.
Fix direction: detect that the process user differs from the signed-in desktop user and warn. Optionally resolve the interactive user's profile paths.

### H2. Offline start wipes the sign-in token
`auth.Manager.Restore` deletes the keyring token on any error except `ErrNotFound`, including network errors. `AuthStatus` is awaited at boot with a 20 s timeout, so the window is blank first, then the login screen appears and also needs the network.
Fix direction: delete the token only when the provider rejects it (`invalid_grant`). On network errors keep the token and show a clear offline message. Shorten the boot wait.

### H3. Published build has no sign-in
`GoogleClientID` defaults to `""`. `build-installer.ps1` only warns when the ID is missing, and `.env.local` does not exist on this machine. Searching the shipped `pcoptimizer.exe` for `apps.googleusercontent.com` finds nothing. The site and privacy policy describe Google sign-in.
Fix direction: make the `-Publish` build fail when `PCOPT_GOOGLE_CLIENT_ID` is unset. Rebuild and republish with the ID set.

### H4. Move copies lose permissions
`robocopy` runs with `/COPY:DAT`, so security descriptors are not copied. Destination files inherit the destination drive root ACLs, often Authenticated Users with write access. Replacing an exe that later runs elevated is a privilege-escalation path. Alternate data streams, EFS and the compression attribute are also lost.
Fix direction: copy with `/COPY:DATSO` (adds ACLs and owner). Refuse destinations that cannot hold ACLs (non-NTFS/ReFS).

### H5. Moved programs and missing drives
A junction to a removable or network drive, or a disk that fails to mount, leaves the program broken without explanation. The Move apps list shows a broken link as a program with size 0 and no hint.
Fix direction: refuse removable and network destinations, tell the user to keep the destination drive connected, and mark broken links ("target missing") in the list.

## Medium

- M1. Cleanup wipes `SoftwareDistribution\Download` without checking `wuauserv` or pending reboot; can corrupt an update in progress. The "already installed" claim is not verified.
- M2. `os.TempDir()` falls back to `C:\Windows` when `TMP`/`TEMP` are unset, and users sometimes point `TEMP` at a drive root or data folder. `walk` has no root sanity check.
- M3. Temp cleanup judges by modification time only. Word `~$` and AutoRecover files, installer staging and tool state older than 24 h can still be live. Empty old subfolders are removed too. No preview of what will go.
- M4. Startup list covers Run keys and Startup folders only. Scheduled Tasks, Store app startup tasks and RunOnce are missing, so the list differs from Task Manager and the Overview "N programs launch at startup" hint undercounts.
- M5. Machine-scope startup state reads and writes only the HKLM `StartupApproved` key. Task Manager likely writes per-user flags to HKCU for HKLM Run entries, so items disabled there may show as enabled. Needs verification.
- M6. Old versions: MSI uninstall strings such as `MsiExec.exe /I{GUID}` open Modify/Repair, not uninstall. `start /wait` returns early for self-relaunching uninstallers (NSIS). A user-cancelled vendor dialog shows "uninstaller failed: " with no reason.
- M7. Old versions: when `EstimatedSize` is missing, `dirSize(InstallLocation)` can walk a whole drive if the location is a drive root or `Program Files`. The mover has a drive-root guard; oldver does not.
- M8. Old versions: version numbers are stripped before grouping, so side-by-side installs (AutoCAD 2022/2024, Photoshop years, JetBrains IDEs) are flagged as duplicates.
- M9. End Process works by PID with only a name check against the critical list. PID reuse between refreshes can hit the wrong process. The app's own `msedgewebview2.exe` children are not protected.
- M10. Driver install: no restore point, one blocking call with no progress, raw COM errors on WSUS/Group Policy machines, no metered-connection warning, `Download()` result code ignored.
- M11. Unsigned always-elevated binary that kills processes and writes HKLM will attract antivirus heuristics. No update check; `version.json` only feeds the website.
- M12. Sign-in is not a real gate. An empty `issuer` in `%APPDATA%\pcoptimizer\auth.json` disables it. Any Google account passes (no `email_verified` check, no allowlist).

## Low

- L1. A stray request to `/callback` with a bad `state` fails the pending login.
- L2. Uninstall leaves the Credential Manager token; "Delete settings" only removes `%APPDATA%\pcoptimizer`. Check against the privacy policy.
- L3. Installer: reinstalling into a different folder leaves the old folder; no rollback on failure.
- L4. `Move()` re-checks `blockReason` without publisher or SystemComponent data. A direct API call could move any folder (for example Documents).
- L5. Process list does per-process `Name()`/`Percent()` for 300+ processes every 2 s; profile CPU use on slow machines.
- L6. `Win32_PnPSignedDriver` WMI query can take 10-30 s with no timeout.
- L7. Read-only files in temp may count as "skipped" if `os.Remove` cannot clear the attribute. Verify.
- L8. No tests for installer, auth, startup, drivers, procs. `frontend/dist` is git-ignored, so a clean checkout needs `npm run build` before `go build`.
- L9. Move apps says "Only one drive was found" when a second disk exists but has no drive letter or is not listed.

## Manual test scenarios

1. Standard user, UAC with admin credentials: do Cleanup, Startup and Recycle Bin hit the right profile? (H1)
2. Launch with Wi-Fi off after a prior login: does it demand a login? Is the token kept? (H2)
3. Fresh install of the published exe: is there a Google login screen? (H3)
4. Move a program from `Program Files`, then compare ACLs with `icacls` on source and destination. (H4)
5. Move a game to a USB drive, eject it, launch the game. (H5)
6. Run Cleanup with Windows Update mid-download, Chrome open and a Word doc unsaved. (M1, M3)
7. Old versions: try an MSI program and an NSIS program; cancel the vendor dialog. (M6)
8. Run the driver check on a machine with Group Policy WU or WSUS. (M10)
9. Install over an existing install in a different folder, then uninstall. (L3)

## Fix log

- H1: `elevation.OtherAccount()` compares the process token user with the Explorer owner in the same session. Overview shows a warning hint; Cleanup and Startup show a banner. Detect and warn only; paths are not remapped to the desktop user.
- H2: `Restore` deletes the token only for `invalid_grant`, `invalid_client` or `unauthorized_client`. Network errors keep the token and show an offline message on the login screen. Boot wait cut from 20 s to 10 s.
- H3: `build-installer.ps1 -Publish` throws when `PCOPT_GOOGLE_CLIENT_ID` is unset. Still to do: create `.env.local`, rebuild and republish.
- H4: robocopy now uses `/COPY:DATSO`. Destination must be NTFS or ReFS (`checkDestVolume`).
- H5: removable, optical and network destinations are refused. Broken junctions are flagged (`broken`, "target missing") and Move back gives a clear message. The confirm dialog tells the user to keep the drive connected.
- Not done: a test that ACLs survive a move (needs a non-trivial ACL fixture), and an end-to-end check of H1 with a real standard user.
